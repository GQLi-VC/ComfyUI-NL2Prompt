## 1. 节点一：`NL2PromptComposer`（显示名「自然语言提示词」）

### 1.1 Python 声明的 widget（`INPUT_TYPES`，顺序即渲染基准顺序）

| 名称 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `natural_language` | STRING, multiline | `""` | 自然语言输入框（真 widget，用户可见） |
| `use_llm` | BOOLEAN | `false` | 是否启用 LLM 重写 |
| `_ui_json` | STRING, multiline | `"{}"` | **隐藏 holder**，承载全部结构化数据（见 §3） |

> 仅这 3 个声明 widget。前端会把 `_ui_json` 设为 `hidden = true` 且 `computeSize = () => [0, -4]`，
> 其余控件（行、按钮、设置按钮）以 `serialize:false` 的 DOM widget 形式插入到 `natural_language` 之后。

### 1.2 可选输入（`optional`）

| 名称 | 类型 | 说明 |
|---|---|---|
| `llm` | `LLM_MODEL` | 接「加载LLM」输出；未接且 `use_llm=true` → 回退模板并告警 |
| `clip` | `CLIP` | 预留（本版不参与组装，接受但不使用） |

### 1.3 输出

| 名称 | 类型 | 说明 |
|---|---|---|
| `positive` | STRING | 最终正向提示词 |
| `negative` | STRING | 最终负向提示词 |
| `text` | STRING | 文本输出端：`Positive:\n{pos}\n\nNegative:\n{neg}` |
| `lora_stack` | LORA_STACK | `[(name, model_strength, clip_strength), ...]` |
| `debug` | STRING | JSON：命中项、注入词、是否走 LLM、回退原因、耗时 |

`RETURN_NAMES = ("positive", "negative", "text", "lora_stack", "debug")`

### 1.4 执行后回填（种子显示）

返回 `{"ui": {"anima_nl": [{"seed": <实际种子>, "used_llm": bool, "fallback": "<原因或空>"}]}, "result": (...)}`
前端 `onExecuted` 读 `message.anima_nl[0]`，在主节点正面渲染一行小字：`上轮种子: <seed>`。

## 2. 节点二：`NL2PromptLoadLLM`（显示名「加载LLM」）

### 2.1 声明 widget

| 名称 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `model_type` | COMBO `["本地模型","云端模型"]` | `"本地模型"` | 前端按值显隐其余项（DOM 重排） |
| `gpu` | COMBO（**nvidia-smi 优先枚举物理卡**，torch 兜底） | **物理 index 1（2060）；单卡时回落 0** | 形如 `"1: NVIDIA GeForce RTX 2060 (12288 MiB)"`；与 `/nl2prompt/gpus` **共用同一实现**（`nodes.list_physical_gpus()`）；`index` 即物理 index，供子进程 `CUDA_VISIBLE_DEVICES` 使用。不得用 `torch.cuda.device_count()` 单独枚举——ComfyUI 启动时若限制可见卡会漏卡 |
| `model_path` | STRING | `"<你的模型目录>\\Models"` | 本地模型根目录（绝对路径） |
| `model_file` | COMBO（`["(请先选择路径后刷新)"]` 起） | — | 由前端调用 `/nl2prompt/scan_gguf` 填充（递归含子目录） |
| `provider` | COMBO `["deepseek","openai","anthropic","custom"]` | `"deepseek"` | 供应商 |
| `base_url` | STRING | 由 provider 自动填 | `custom` 时留空由用户填 |
| `cloud_model` | STRING | `""` | 云端模型代号，手填 |
| `_llm_json` | STRING, multiline | `"{}"` | 隐藏 holder（见 §4） |

### 2.2 输出

| 名称 | 类型 |
|---|---|
| `llm` | `LLM_MODEL` |

**`LLM_MODEL` 值结构**（Python dict，**绝不含 api_key 明文**）：
```json
{"mode":"local|cloud","provider":"deepseek","base_url":"https://api.deepseek.com/v1",
 "model":"deepseek-chat","gpu_index":0,"gpu_name":"NVIDIA GeForce RTX 3060",
 "local_path":"<你的模型目录>\\Models\\qwen3.5\\qwen3.5-9B\\Qwen3.5-9B-Q4_K_M.gguf",
 "sampling":{"top_k":40,"top_p":0.9,"temperature":0.7,"max_tokens":1024,"seed":-1},
 "runtime":{"ctx":8192,"timeout":120}}
```

## 3. 主节点 holder JSON（`_ui_json`）完整 schema

```json
{
  "schema": 1,
  "character_rows": [
    {"id": "r1", "name": "遐蝶", "trigger": "castorice, purple hair, purple eyes", "outfit_hint": "假日皮肤"}
  ],
  "style_rows": [
    {"id": "s1", "name": "@nixeu", "trigger": "@nixeu, soft light"}
  ],
  "text_map": [
    {"id": "t1", "find": "霓虹街道", "prompt": "neon-lit street, rain, wet ground", "target": "positive"}
  ],
  "system_prompt": "",
  "negative_base": "lowres, bad anatomy, text, watermark, extra digits, worst quality",
```

## 5. 组装算法（后端，模板模式；LLM 模式见 §7）

输入：`natural_language`、holder JSON、`store` 数据、可选 `llm`。

```
positive_parts = []
negative_parts = [normalize(negative_base)]

for row in character_rows:
    trigger = row.trigger.strip()
    if not trigger: continue
    positive_parts += split_tokens(trigger)                 # lora激活词（用户手填）
    char = store.resolve_character(row.name)                # 别名/显示名匹配
    if char:
        # B3 多服装隔离：命中具体服装则只注入该服装，其余服装词进 negative
        outfit, siblings = store.resolve_outfit(char, row.outfit_hint)
        positive_parts += split_tokens(char.activation_words)
        if outfit:
            positive_parts += split_tokens(outfit.activation_words)
            positive_parts += split_tokens(outfit.prompt)
            if outfit.lora_name: lora_stack.append(...)
        for sib in siblings:                                # 同角色其它服装（**差集抑制**，2026-11-15 裁决）
            sib_words  = set(split_tokens(sib.activation_words)) | set(split_tokens(sib.negative_suppress))
            keep_words = set(split_tokens(当前命中 outfit 的 activation_words)) | set(split_tokens(character.activation_words))
            negative_parts += [w for w in sib_words if w not in keep_words]
        # 为什么是差集：只用 negative_suppress 会漏掉 sibling 的辨识度主词（如原皮的
        #   strapless dress / frilled dress），导致换装渗透；而整份 activation_words 直接压
        #   又可能把两套服装共享的词压掉（自伤）。差集取二者之并再减去"当前 outfit +
        #   角色级"词表，既彻底又安全。keep_words 必须含角色级词，否则人物身份词被压。
        # 输出顺序：sib.activation_words 后 sib.negative_suppress，保持稳定。
        # 【语义裁决 2026-11-15，lead】outfit.negative_suppress 的语义是
        #   「该服装自身的区分性标签」，选中其它服装时用它来压制这套。
        # 因此新增服装只需填自己的词，其它服装自动获得压制，无需互相维护。
        # 注意：任务书 §6 示例里把 dreamy.negative_suppress 写成原皮的标签，
        #   那是任务书示例的字面写法，与本节伪代码方向相反；二者必须二选一，
        #   本契约采用本节伪代码（nodes.py 与 data/characters.json 均按此实现与填充）。
        if char.lora_name: lora_stack.append(...)
    if row.outfit_hint: positive_parts += split_tokens(row.outfit_hint)  # 数据层未命中时仍当普通词用

for row in style_rows:
    positive_parts += split_tokens(row.trigger)
    style = store.resolve_style(row.name)
    if style:
        positive_parts += split_tokens(style.activation_words) + split_tokens(style.prompt) + style.artist_tags
        if style.lora_name: lora_stack.append(...)

for m in text_map:                                          # A3 文字指定提示词
    if m.find and m.find in natural_language:               # 子串、大小写不敏感
        (positive_parts if m.target=="positive" else negative_parts).append(m.prompt)

positive_parts.append(natural_language)                     # 原始自然语言置于末尾
positive = dedupe_join(positive_parts, sep=", ")
negative = dedupe_join(negative_parts, sep=", ")
```
- `split_tokens(s)`：按 `,` 切分、去空白、过滤空串
- `dedupe_join`：大小写不敏感去重（保留首次出现顺序）
- 若 `use_llm=true` 且 `llm` 已连接：把上式结果作为"草稿"，交给 LLM 优化（§7）；LLM 失败 → 原样返回上式结果 + `debug.reason`

## 7. LLM 调用契约

**请求**：OpenAI 兼容 `POST {base_url}/chat/completions`
```json
{"model":"...","temperature":0.7,"top_p":0.9,"max_tokens":1024,
 "response_format":{"type":"json_object"},
 "messages":[{"role":"system","content":"<system_prompt 渲染后>"},
             {"role":"user","content":"<自然语言 + 草稿 positive/negative + 已选约束>"}]}
```
- `top_k` 非 OpenAI 标准字段：**不发送**给云端；本地 llama-server 可作为额外字段发送（供应商支持时）
- 云端不支持的字段一律不发，避免 400

**期望响应**（严格 JSON）：
```json
{"positive":"...","negative":"...",
 "debug":{"characters":[],"outfits":[],"styles":[],"injected_triggers":[]}}
```
**解析规则**：先 `json.loads`；失败则用正则取首个 `{...}` 平衡块再解析；仍失败 → 回退。
**校验**：`positive` 必须是非空字符串，否则视为失败。
**超时**：默认 30s（`runtime.timeout` 可调），只尝试 1 次，不重试。

**system prompt 默认模板**（`store.default_system_prompt()` 返回，前端「恢复默认」还原此值）：
```
你是 Anima 文生图模型的提示词重写器。把用户的自然语言描述重写为 Anima 更容易执行的提示词。

已知可用角色与服装：
{{character_presets}}

已知可用画师/风格：
{{style_presets}}

当前用户选择：
{{selected}}

规则：
1. 只注入当前选中服装的触发词，不要注入同角色其他服装的触发词。
2. 保留角色 LoRA 激活词、服装触发词、风格触发词。
3. 用具体视觉事实替代空洞形容词。
4. 输出 JSON：{"positive":"...","negative":"...","debug":{"characters":[],"outfits":[],"styles":[],"injected_triggers":[]}}
5. 不要输出解释性文字，只输出 JSON。
```
`{{...}}` 占位符由后端填充；用户自定义文本中的占位符同样生效，缺失占位符时直接原文使用。

## 8. 错误码

| code | 含义 | 处理 |
|---|---|---|
| `llm_not_connected` | `use_llm=true` 但 `llm` 输入未连接 | 回退模板 + 告警 |
| `llm_key_missing` | 云端模式无 api_key | 回退 + 明确提示去设置 |
| `llm_timeout` | 超时 | 回退 |
| `llm_bad_json` | 响应无法解析 | 回退 |
| `llm_http_<code>` | 非 200 | 回退，detail 带响应片段（≤200 字） |
| `llm_empty_positive` | positive 为空 | 回退 |
| `llm_skill_check_failed` | skill 校验连续 2 次不合格（含重试 1 次） | 回退模板；`debug.skill_check` 保留 issues 与 `retried:true` |
| `local_model_missing` | 本地 gguf 不存在 | 回退 + 指明路径 |
| `runtime_start_failed` | llama-server 启动失败/未就绪 | 回退 + 日志路径 |
| `path_not_found` | 扫描路径无效 | 前端提示 |
| `store_corrupt` | 数据 JSON 损坏 | 用内置最小默认值继续（不崩） |
| **`safetensors_unavailable`** | 新增 v3：`llm_local_hf.py` 不可用或缺 `chat()` | 回退，提示改用 GGUF/云端 |
| **`safetensors_failed`** | 新增 v3：safetensors 推理其它失败 | 回退模板 |
| **`safetensors_load_failed`** | 新增 v3：模型加载失败（如非 causal LM 架构） | 回退 + 原始异常 |
| **`safetensors_not_found`** | 新增 v3：目录缺 `config.json` 或没有权重 | 回退 + 指明目录 |
| **`safetensors_need_dir`** | 新增 v3：`model_dir` 未填写/不存在 | 前端提示 |
| **`local_model_oom`** | 新增 v3：加载时显存不足 | 回退，detail 明确「建议改用 GGUF」 |
| **`cloud_model_empty`** | 新增 v3：云端模式 `cloud_model` 为空 | 回退 + 提示填写（**原误归到 `llm_http_0`**） |
| **`cloud_base_url_empty`** | 新增 v3：云端模式 `base_url` 为空 | 回退 + 提示选供应商（**原误归到 `llm_http_0`**） |
| **`bad_locale`** | 新增 v3：`ui_locale` 不是 `auto/zh/en` | 拒绝写入（**原误归到 `bad_request`**） |
| **`bad_skill_id`** | 新增 v3：skill id 不符合 `^[a-z0-9-]+$` 或超 64 字符 | 读/写/删三条入口都返回它 |
| **`skill_not_found`** | 新增 v3：skill 不存在 | 前端提示 |
| **`skill_exists`** | 新增 v3：新建时 id 已存在 | 前端提示换名 |
| **`skill_protected`** | 新增 v3：试图删除默认 skill | 前端提示不可删 |

所有回退都必须写入输出的 `debug`：`{"used_llm":false,"fallback":"<code>","detail":"..."}`。

**v3 双语（§15.5）**：所有错误响应同时带 `detail_zh` / `detail_en`（`detail` 保留兼容）。实现方式是 `routes.py` 的 `_ERR_EN` 字典（33 个 code）+ `_error_en_for()`，**61 个调用点无需传参自动获得英文**；`llm_http_<n>` 与 `safetensors_*` 这类动态码由函数按前缀生成。

## 9. 前端契约（frontend-ui）

### 9.1 主节点 DOM 结构（`natural_language` 之后依次插入）
1. `⚪ 自然语言处理` 折叠头（点击 toggle，状态写 `_ui_json.ui.collapsed_main`）
2. 角色行容器：每行 = `name` 输入 + `trigger` 输入 + `outfit_hint` 输入 + 删除按钮
3. 风格行容器：每行 = `name` 输入 + `trigger` 输入 + 删除按钮
4. 按钮行：`【添加指定的角色lora激活词】` `【添加指定的画师画风/风格激活词】`
5. `⚙ 设置` 按钮 → 打开设置窗口（§9.3）
6. 种子小字（`onExecuted` 回填）

### 9.2 `_ui_json` holder 约定（同 `anima_prompt_boxes.js` 范式）
```js
const holder = node.addDOMWidget("_ui_json_view", "anima_nl_holder", document.createElement("div"), {
  hideOnZoom: false,
  getValue: () => JSON.stringify(state),
  setValue: (v) => { const p = parse(v); if (p) { state = merge(defaults, p); render(); } },
});
holder.hidden = true;
holder.computeSize = () => [0, -4];
```
- 所有行/按钮 widget 设 `serialize = false` 且 `computeSize` 返回真实高度
- 每次变更后 `node.setDirtyCanvas(true,true); node.graph?.change?.()`
- `onConfigure` 时必须能从 `widgets_values` 里正确取回 `_ui_json`（按名称定位，不靠下标）
- `onNodeCreated` / `onConfigure` / `onExecuted` 三个钩子都要挂（参考 `anima_prompt_composer.js`）

### 9.3 设置窗口（两个节点共用一套窗口基类）
- `document.body` 下创建：遮罩 `.anima-nl-overlay`（`position:fixed;inset:0;z-index:10000`）+ 面板 `.anima-nl-dialog`
- 关闭方式：右上角 ✕、点遮罩、`Esc`
- 面板内 `pointerdown` 一律 `stopPropagation`，避免触发画布拖拽
- 窗口打开状态**不写入** workflow（仅内存变量）

**主节点窗口**（标题「提示词设置」），3 个 Tab：
1. **提示词替换**：`text_map` 行编辑器（`find`｜`prompt`｜目标 positive/negative 切换｜删除）+ 添加按钮
2. **系统提示词**：多行 textarea + `恢复默认` 按钮（`confirm()` 二次确认，取消不变）+ `保存`
3. **负面基础词**：`negative_base` 多行 textarea
底部：`保存` / `取消`（取消丢弃未保存修改）

**LLM 节点窗口**（标题「LLM 设置」），2 个 Tab：
1. **采样参数**：`top_k`(0–100) / `top_p`(0–1) / `temperature`(0–2) / `max_tokens` / `seed`（`-1` 勾选框=每次随机，否则数字输入）+ `last_seed` 只读显示；云端模式下 `top_k` 灰化并提示「云端不支持」

## 13. 实测裁决补充（2026-11-15，llm-runtime 实测后新增）

### 13.1 本地 llama-server **必须**加 `--reasoning off`
Qwen3.5-9B 是 thinking 模型：不加该参数时 `message.content` 恒为空、思考内容全在 `reasoning_content`，`max_tokens` 会被思考吃光（实测 max_tokens=2048 → 44.8s、`finish_reason=length`、content 长度 0）。
- `--reasoning-budget 0` **无效**；从 reasoning 里正则提取 JSON 会得到占位符草稿（假阳性，比失败更危险）
- `--reasoning off` **是唯一有效解法**，§7 重写任务 2.5–3.4s 直接返回合法 JSON
- 实现要求：`runtime.py` 启动前用 `llama-server --help` 探测该参数是否存在，不支持则省略并告警；可用 `llm["runtime"]["reasoning"]`（`off`/`on`/`auto`）或环境变量 `ANIMA_LLM_REASONING` 覆盖；该值**并入复用键**
- **任何人不得在别处自行启动 llama-server 而漏掉该参数**

### 13.2 `secrets.json` 单一真源 = `providers.py`
同一文件曾被两端各写一套格式（`{"api_key":...}` vs `{"<provider>":...}`）导致互不认。
裁决：
- **读写 API 密钥只由 `providers.py` 负责**；`llm_client.py` / `nodes.py` / `routes.py` 一律调用 `providers`，**不得自行读写该文件**
- 文件格式：`{"<provider>": "<key>", "_default": "<key>", "updated_at": "<iso>"}`
- `providers.py` 保留向后兼容读取：遇到历史 `api_key` 键归一到 `_default`

### 13.3 api_key 解析优先级（覆盖契约 §11 原描述）
```
ANIMA_LLM_API_KEY_<PROVIDER大写>  >  ANIMA_LLM_API_KEY  >  secrets.json[<provider>]  >  secrets.json["_default"]
```
- `providers.resolve_api_key(provider) -> (key|None, source)`，`source ∈ {"env_provider","env_global","file","none"}`
- `nodes.py` 的 `_resolve_api_key` **必须**直接消费该元组，不得自行再拼一层 env 查询（否则会屏蔽分供应商变量）
- 兼容别名 `providers.api_key(provider) -> str|None` 可保留

### 13.4 实测默认值（取代零散默认）
| 项 | 默认 | 依据 |
|---|---|---|
| `ctx` | 8192 | 显存 5.34 GB / 12 GB，实测无 OOM |
| `timeout` | 120 | 冷启动 4–12s，留 10 倍余量 |
| `ngl` | 99 | 全卸载成立 |
| `max_tokens` | 1024 | §7 实际只用 141–200 tokens |
| `reasoning` | `off` | 见 §13.1（硬性） |
| 本地 LLM 绑卡 | **强制 GPU1** | `gpu_index=0` 会被改绑 1 并告警；需放开时设 `ANIMA_LLM_ALLOW_GPU0=1` |
| 端口 | 8081 起自动挑 | 黑名单 8080 / 8188 / 8199 |

### 13.5 实现细节确认（backend-core 交付后补注，均为向后兼容）

1. **节点返回值封装**：`NL2PromptLoadLLM.load` 返回 `{"ui":{"anima_llm":[{"seed":int}]},"result":(llm,)}`，`NL2PromptComposer.compose` 返回 `{"ui":{"anima_nl":[{"seed","used_llm","fallback"}]},"result":(5元组)}`。这是 ComfyUI 标准 ui 回填封装，§2.2 只约束输出**类型**，不约束封装形式。
2. **`/secret` 可选 `provider` 字段**：`POST /nl2prompt/secret {"api_key":"...","provider":"deepseek"}` 写分供应商槽位；不传则写 `_default`。响应结构不变（`{"ok","configured"}`）。**必须只接受显式含 `api_key` 的 JSON**——请求体畸形时不得当作"空串清除"处理（会静默删掉用户密钥）。
3. **`compose_plain(nl, ui, data=None)`** 返回除 §12 的 4 键外，额外带 `text` 与 `seed`；实现上把「模板组装」与「LLM 重写」拆为 `compose_plain`（纯函数、无网络）与 `compose_with_llm`（节点实际调用），保证无 GPU 可单测。
4. **路由注册幂等**：`aiohttp 3.13.3` 的 `RouteTableDef` 没有 `.routes` 属性，幂等检查需兼容 `_items / routes / _sequence` 三种取法，否则插件热重载会重复注册并抛 `add_routes` 冲突。
5. **`IS_CHANGED`**：`sampling.seed < 0` 时必须返回 `time.time()`，否则 ComfyUI 执行缓存会使"每次生成回填新种子"（A5）失效；`seed` 固定时返回稳定哈希。


`nodes.py` 必须暴露纯函数便于无 GPU 单测：
```python
def compose_plain(natural_language: str, ui: dict, data: dict|None=None) -> dict
    # 返回 {"positive":str,"negative":str,"lora_stack":list,"debug":dict}
```
单测直接 `from nodes import compose_plain`，无需启动 ComfyUI。

- Composer 在 `compose_with_llm()` 的 `finally` 里执行 ——**成功与失败两条路径都卸载**
- **`unload` 与 `stop_all` 的边界**：
  - `runtime.unload(llm)`：按 `llm["mode"]` 只卸**这一个**（`local` → 对应的 llama-server；`safetensors` → HF 模型；`cloud` → no-op）。优先使用
  - `runtime.stop_all()`：卸**全部**，只在 `unload` 不存在时作兜底（兼容旧 `runtime.py`）
- **双保险**：safetensors 路径下 `llm_local_hf.chat()` 内部也会按 `unload_after_use` 卸载一次；外层再调 `runtime.unload(llm)`。两次幂等，显存不会泄漏（`runtime` 模块缺失时 chat 那次仍生效）
- **`debug.unloaded` 语义 = 「本次执行结束后该本地模型确实不再驻留显存」**，不是「成功调用了卸载函数」：
  - safetensors：以 `runtime.loaded_info()["safetensors"]["loaded"]` 二次确认，取不到状态时退化为「动作已调用即 True」
  - local / cloud：动作完成即 True（local 多模型共存时列表判空会误报）
  - 任何异常只记日志，**绝不中断出图**

```
{"mode": "local" | "safetensors" | "cloud", "provider", "provider_label", "base_url",

 "runtime": {"ctx", "timeout", "port", "unload_after_use"}}
```
- `mode == "safetensors"` 时 `_resolve_llm_target` 返回 `(mode, "", model)`，**不走 HTTP**，由 `_call_safetensors_once` → `llm_local_hf.chat(llm, messages)` 生成

- 旧 `NL2PromptLoadLLM` 保留，显示名「加载LLM（旧·本地/云端合一）」

**safetensors 运行时的错误码**（`llm_local_hf.py`）：
`safetensors_need_dir` / `safetensors_not_found`（缺 config.json）/ `safetensors_load_failed` / `local_model_oom` / `safetensors_unavailable`（模块缺失）/ `safetensors_failed`（其它）

**平台限制（实测，必须告知用户）**
- GPU1（RTX 2060，12 GB）可用 **10.95 GiB**；6B fp16 ≈ **13.97 GiB → 必 OOM**，detail 明确提示改用 GGUF
- Turing（SM 7.5）**不支持 bf16 推理 kernel** → `_effective_dtype()` 自动降 fp16
- HF 缓存是符号链接，扫描必须跟随（否则误判"没有权重"）
- transformers ≥5 用 `dtype=`，<5 回退 `torch_dtype=`

### 15.9.3 新增路由 `GET /nl2prompt/scan_safetensors`

主路由 19 → **20 条**（旧前缀别名同步 20 条）。

```
GET /nl2prompt/scan_safetensors?path=<model_dir>
→ {files:[{name,path,size_mb,dir}], root, error, total_found, require_config:true}
```

**与 `scan_gguf` 的差异**：只返回**所在目录含 `config.json`** 的 `.safetensors` —— HuggingFace 模型目录必须带 config 才能被 `AutoModelForCausalLM` 加载，因此后端直接过滤裸权重，避免用户选到加载不了的文件。
